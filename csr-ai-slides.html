Problem + Scope

CSR agents context-switch across 5+ systems per case. 3.8K admin cases/month. 2.7 days avg TTR for work that should take 5 minutes.

The User

CSR agents in Salesforce Service Cloud — first line for admin access cases. Every case starts from scratch across Okta, CSP, SF, KB, AdminSite in parallel. No guided flow, no pre-fetched context.

02 / 04

Workflow + Agent Model

RAG-gated eligibility. LLM classifies, deterministic rules execute. Every write requires CSR click-confirm — no exceptions.

The permanent boundary
AI gets you into the right scenario (RAG gate + LLM classifier). Rules handle everything once you're in it. Decision tree traversal is permanently deterministic — now and after V1.
How the eligibility gate works

Hard rule. False → Hermes renders, exit.

RAG Vector similarity ≥ 0.70?
4 fields embedded → compared against scenario library. Yes → Activate. No → Hermes.

LLM Classifier (Post-MVP)
Case text + 12 signals → scenario ID + confidence %. Confidence < 70% → competing hypotheses shown.

Failure handling
API timeout — Chip shows Unavailable. CTA withheld if signal required, explicit reason shown.
Model misclassification — CSR overrides scenario. Feedback captures it. Calibration adjusts.
Action outside allow-list — Server-side hard block. Logged as security event.
Action execution failure — Inline error + retry. Fallback: manual instruction. Audit log records failure.
Hermes coexistence — decided Sep 24 (Siddhartha sync)
When case passes RAG gate: Admin Assistant replaces Hermes panel. AI Summary and Evidence/Reasoning preserved. Ask AI button replaced by Admin Assistant surface. Key Actions Required replaced by Recommended Action hero card. Non-eligible cases: Hermes renders as normal, no UI change visible to CSR.
